# 界面恢复与进度记录

## 写入顺序与记录

项目的 `data/` 已忽略 Git。每次执行建立 `data/runs/<本地日期时间>-boss-zhipin/`，记录 `events.jsonl` 和可选的上限截图。使用当前可用的本地文件工具写入；不要在 `cua_repl` 中使用未文档化的文件系统接口。技能目录只保存流程，不保存用户 Cookie、简历、账号标识或聊天内容。

开始记录本次参数，包括时区、时间、数量/位置/上限停止模式、薪资门槛、公司偏好、当前查询和城市。执行前如无法可靠写记录，先说明无法保障跨重置恢复，不宣称已持久化。

逐岗位追加事件，避免只在一整批完成后保存总数。一次记录示例（字段值按实际读取填写）：

```json
{"time":"2026-10-21T10:00:00+08:00","event":"send_intent","run_id":"20261021-100000","result_set":"query=Agent;city=北京","position":3,"job_key":"job_detail/<实际岗位标识>","company":"示例公司","title":"Agent工程师","salary":"25-40K","salary_upper_k":40}
{"time":"2026-10-21T10:00:03+08:00","event":"send_confirmed","job_key":"job_detail/<实际岗位标识>","evidence":"已向BOSS发送消息"}
{"time":"2026-10-21T10:00:04+08:00","event":"success_dialog_closed","job_key":"job_detail/<实际岗位标识>"}
```

- 在点击“立即沟通”**之前**追加 `send_intent`。
- 观察到成功回执后立即追加 `send_confirmed`，随后关闭成功弹窗，再追加 `success_dialog_closed`。
- 其他事件：`skipped`（附原因）、`already_contacted`、`notice_120`、`uncertain`、`limit_reached`、`user_stopped`、`run_finished`。仅成功回执计入新增成功；已沟通、跳过、尝试、提醒和上限事件均不计入。
- 保存岗位 URL 时只保留岗位标识，去掉 `securityId` 等查询参数。若界面只显示省略 URL，不臆造完整标识；记录公司、职位、薪资、结果集和位置，明确 `identity_confidence: partial`。
- 时间逐事件获取，不事后编造开始、结束或耗时。跨午夜保留本次总数，但网站当日额度只以其提示为准。
- 上限事件记录提示原文；若用户要求保留页面，只做读取或截图，不为整理记录点击或跳转浏览器。

## 任何异常都暂停当前批次

每次动作后先取最新界面，再决定下一动作。工具重置、未知弹窗、提醒或回执缺失时停止循环；不能让批处理继续选择下一岗位。

避免重用当前会话之外的元素索引。索引、可访问性树层级、列表容器深度都可能变化；必须用当前工具观察验证，不依赖固定“十层缩进、每两个链接是一张卡片”等解析假设。广告、页脚和详情里的链接不能当作岗位。

## 等待、超时与工具重置

- 依赖界面工具自身的等待及合理的重新观察，不紧密循环大量读取，也不固定睡眠数秒替代验证。
- 推荐一岗位一个工具调用；小列表可做短批次，但每次必须完整经过“意图 → 回执 → 留在此页 → 关闭确认”。批次中发生未知状态立即退出。
- 长列表曾使单次捕获变慢、整批调用超时并重置 REPL。观察到变慢后把批次缩小，不继续靠增大批量弥补延迟。
- 重连后先读取当前界面和日志。如果已显示最终上限，直接停止并保留。
- 若当前有成功弹窗：与最近的待确认意图对应后补记成功、点击“留在此页”、验证关闭；不能为了恢复从头重复发送。
- `send_intent` 无成功记录时，不自动重发。重新选择并核对同一岗位，若显示“继续沟通”，记录“已沟通、恢复后确认”；没有原始成功回执时与严格新增成功数分开。若仍无法确定，标记 `uncertain` 并暂时跳过，报告实情。
- 日志只缺“成功弹窗已关闭”时，先确认弹窗状态，不重复累计成功。

## 次数提醒

120 次提醒可能出现在成功弹窗之前。该岗位的点击仍处于待确认状态；点击“好/确认”后观察回执，不再按“立即沟通”。

历史执行曾在提醒未处理时继续选择岗位，产生多个堆叠提醒。不要复现。若恢复时已经堆叠：

1. 暂停新发送，先确定是否有最终上限；有则原样保留、立即停止。
2. 仅在仍明确为 120 次中间提醒且用户授权继续时，逐个处理最上层提醒，每次读取新状态。
3. 观察并记录随后出现的每个成功回执，再关闭其“留在此页”。不能凭当前右侧职位把所有堆叠回执归到同一岗位。
4. 用待确认日志对齐岗位；对不上的标记未知，不虚构归属或数量。所有中间弹窗处理完才恢复选岗。

## 登录、安全检查与搜索结果

- 需要重新登录或人工安全检查时暂停，交由用户正常完成。不得解决未获当次确认的验证码、伪装请求头或用其他技术绕过校验。
- 普通 Chrome 曾正常，而 Playwright/CDP 测试曾发生空白页、安全页面循环。当前流程不读取 Cookie 文件导入，也不改动用户 Chrome 的登录配置。
- 列表位置随切换查询、刷新、排序而变化。每次结果集单独编号，跨结果集按岗位标识去重。先审查公司和薪资，再发送。
- 列表耗尽时先确认是否真到页脚或仍在加载；用户允许相关岗位范围时，可使用搜索框查找 Agent、大模型等相关岗位。不要自动点击用户要求手动操作的求职期望区域，不为凑额度扩大到无关岗位。
