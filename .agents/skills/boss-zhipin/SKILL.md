# BOSS 直聘职位沟通

## 使用范围

复用用户正常使用、已登录的 Chrome，通过当前环境提供的 `cua_repl` 系统界面工具操作 `https://www.zhipin.com/web/geek/jobs`。这是由 Codex 执行的操作流程，不是独立运行的 Python 程序。工具不可用时说明具体缺失，不擅自换成 Playwright、CDP、PyObjC 或其他技术栈。

本技能本身不授权发送消息。开始沟通前，明确本次用户要求的岗位范围、数量或停止条件；遵守最新指令及“停”。用户只要求查看、修改技能时，不操作网站。不要因为读取本技能而关闭浏览器里现有的上限提示。

## 默认偏好

开始前读取 [references/filters.md](references/filters.md)，应用本用户保存的公司与薪资条件。用户本次明确修改的条件优先。

- 使用网站默认招呼语；不额外编写、发送聊天内容或主动上传附件。
- 数量目标以用户要求解释：指定第 N～M 个是列表位置范围；“再沟通 N 个”是新增成功数量，跳过项不占数。用户后来改为“直到网站达到上限”，就以真实上限提示为停止条件。
- 不把“150 次”当成本地按钮点击数。一次成功回执、唯一岗位、唯一 BOSS、网站当天额度是不同口径；不得根据本地计数声称网站当天已达 150。
- 确认沟通成功后点击“留在此页”。出现最终上限提示时立即停止，保留原页面及弹窗，不点击“确定”、刷新、返回或继续选择岗位。

## 单岗位操作

1. 首次或重置后按 `cua_repl` 返回的当前文档初始化。选择用户正在使用的 Chrome 窗口，确认页面和登录状态；不要新建自动化登录浏览器。用户已禁止自动点击“大模型算法(北京)”求职期望，让用户手动切换该区域。
2. 从最新界面读取岗位、公司、薪资和当前筛选条件。使用职位链接或岗位标识去重；列表序号只在当前结果集内有效。没有完整链接时，记录公司、标题、薪资和结果集，不能仅凭同名岗位判断重复。
3. 在发送前核对筛选条件。每批先审查候选公司，避免读取到公司名后直接批量发出招呼。信息不足的岗位暂时跳过并记原因。
4. 点击岗位，重新读取界面，核对右侧公司和职位。列表可能附加“双休”“五险一金”等后缀；只有能核实为同一岗位时才继续，不以标题不完全一致为由盲目点击。
5. 若右侧显示“继续沟通”，视为已沟通并跳过，不点击它。若显示“立即沟通”，先记录发送意图，再点击一次。
6. 读取新状态，按以下顺序处理；任何未识别状态都暂停本批，不转去下一岗位：
   - **最终额度上限**：如“您已达到沟通上限”“您今天已与150位BOSS沟通”。停止全部界面动作，保留弹窗；可以只读截图核实。
   - **120 次提醒**：如“今天已与120位BOSS沟通，还剩30次沟通机会”。这是中间提醒，不是最终上限。用户要求继续时，点击其实际显示的“好”或“确认”，继续观察当前待发送结果。不要再次点击“立即沟通”，也不要先去下一岗位。
   - **发送成功**：必须观察到“已向BOSS发送消息”，才能记为新增成功。记录回执后点击该成功弹窗的“留在此页”，重新读取状态确认弹窗关闭，再进入下一岗位。
   - **登录、安全检查、网络错误、未知弹窗或等待超时**：保留当前现场，按恢复参考处理；缺少成功回执时不得累计成功或自动重发。
7. 每一个成功或跳过都立即更新进度；用户要求的成功数量已满足则停止，不额外发送一个来“测试”。

## 状态与恢复

执行前及发生加载、超时、提醒、工具重置时读取 [references/recovery.md](references/recovery.md)。按参考的 JSONL 记录格式把进度存入项目的 `data/runs/`，该目录已被 Git 忽略。不要仅依赖 REPL 变量或对话中的总数。

- 所有界面动作只通过当前允许的界面工具完成；每次操作后读取最新状态再决定下一步。不要保存按钮索引、坐标、完整可访问性树或含会话参数的 URL 用于下次执行。
- 优先一岗位一个工具调用，或按耗时采取很短的批次。加载岗位增加后缩小批次，避免整批超时丢失进度。
- 新结果集单独编号。默认沿当前结果列表筛选；耗尽后可搜索 Agent、大模型等相关词继续，不更改用户明确限定的岗位、城市或其他范围。用户要求固定位置范围时不得换搜索词凑数。
- 如遇网站安全检查，交给用户处理，不绕过检查。需要用户操作时说明当前阻碍，不能谎称已完成。

## 完成报告

说明实际停止原因、新增成功数量（仅在有可靠记录时）、未确认项、最终页面是否保留。对于额度任务，引用网站实际提示区分当天额度与跨日期累计操作；仅凭设备日期变化不推断额度已刷新。

原始项目有邮件通知需求，但当前界面流程未接入邮箱、收件人或发送配置。不得宣称邮件已发送，也不擅自寻找收件人。用户要求实现通知时单独完成配置；不为发送通知关闭上限页面。
